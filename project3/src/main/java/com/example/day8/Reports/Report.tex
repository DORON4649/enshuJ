\section{目的}
本課題の基本仕様では、描画オブジェクトの管理上限(maxObject)を超過した際に、古い順から自動的に削除される仕組みとなっていた。

しかし、この仕様では、「直前に間違えて描画したオブジェクトだけを消す」といった操作ができず、不要な図形を消すために上限までダミーの図形を描き続けなければならないという操作上の課題があった。

そこで、本レポートでは、実用的な描画ソフトとして動作させるため、任意の図形を直接選択し、個別に削除できる機能を拡張することにした。

\section{課題}
前章の目的を達成するため、指定された必須課題に加え、以下の機能を実装した。
\begin{itemize}
    \item \textbf{描画オブジェクトの選択機能} \\
        キャンバス上に描画された図形をクリックもしくはドラッグすることで、対象の図形を選択状態にする機能。
    \item \textbf{選択図形の個別削除機能} \\
        選択された特定の図形データのみを、リストから除外し、再描画する機能。
    \item \textbf{ツール切り替えGUI} \\
        描画モードと選択・削除モードなどを切り替えるためのUIの配置。
    \item \textbf{Undo機能} \\
        直前に行った操作を取り消す機能。
\end{itemize}

\section{理論}
前章の課題を実現するために、本プログラムでは以下の理論及び技術を活用した。
\begin{itemize}
    \item \textbf{ArrayListによる動的なデータ管理}\\
        描画された複数の図形オブジェクトを保存するために、要素数が可変である \texttt{ArrayList} クラスを用いた。配列とは異なり、要素の挿入・削除が容易であることを活かし、リストの中間要素を削除(\textt{remove})する「個別削除」や、リストの末尾要素を削除する「Undo処理」を効率的に実現している。

    \item \textbf{座標計算による当たり判定(図形選択時)} \\
        図形を選択可能にするため、マウスクリック時に取得した座標(x, y)と、各図形インスタンスが保持している位置・サイズ情報を比較する巣学的な当たり判定アルゴリズムを実装した。これにより、クリックされた位置に存在する図形オブジェクトを特定(選択)している。

    \item \textbf{イベントリスナーと状態管理(ツール切り替え)} \\
        GUI（ボタン等）の操作を \texttt{ActionListener} で検知し、アプリケーションの現在の「モード(描画・選択・削除など)」を表す内部変数（状態）を切り替える手法を用いた。この状態に応じて、 \textt{MouseListener} が検知したマウス操作のふるまいを動的に分岐させている。

    \item \textbf{ポリモーフィズムの活用} \\
        描画する各図形クラスを共通のスーパークラスから派生させ、描画（\textt{paint}）や当たり判定の処理をオーバーライドさせた。これにより、図形のリストを操作する際に個別の図形の種類を意識することなく統一的なメソッド呼び出しが可能となり、プログラムの拡張性を高めている。
\end{itemize}
